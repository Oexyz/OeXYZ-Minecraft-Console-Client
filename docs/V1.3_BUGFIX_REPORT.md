## Fixed P1 Release Blockers

| ID | Finding | Implementation and regression coverage |
|---|---|---|
| P1-1 | Linux changed caller-owned parent directories to `0700` | [`PrivateFileSystem`](../src/OeXYZ.Core/PrivateFileSystem.cs) protects only newly created OeXYZ directories and generated files. Core tests and WSL verify that an existing `0755` directory remains unchanged while profiles, locks, and keys receive mode `0600`. |
| P1-2 | Terminal control sequences could enter through chat, MOTDs, names, and errors | The central [`TerminalTextSanitizer`](../src/OeXYZ.Protocol/TerminalTextSanitizer.cs) neutralizes C0/C1 controls, ESC, BEL, CR/LF/Tab, and U+2028/U+2029. Protocol, Session, CLI, dashboard, and integration sinks use it; hostile chat, status, and player-name fixtures are covered. |
| P1-3 | Passwords and tokens could reach history, logs, and support data | [`SensitiveDataRedactor`](../src/OeXYZ.Core/SensitiveDataRedactor.cs) handles namespaced login commands, quoted values, and bounded structured JSON, including escaped keys and array/object values. Outgoing chat is redacted at the source in [`MinecraftConnection`](../src/OeXYZ.Protocol/MinecraftConnection.cs); Session, CLI, and support-package tests cover the complete sink chain. |
| P1-4 | Multi-account sessions collided on log files, and logging failures remained invisible | [`ConsoleSession`](../src/OeXYZ.Session/ConsoleSession.cs) uses milliseconds, account/server names, both IDs, and atomic GUID reservation. Asynchronous write failures remain visible as `LogException` and affect process status. |
| P1-5 | Display names could select the wrong Microsoft identity | [`ProfileTransferService`](../src/OeXYZ.Core/ProfileTransferService.cs) matches only by ID and safely renames name collisions. Central profile validation rejects duplicate names and IDs. In addition, [`MicrosoftAccountStore`](../src/OeXYZ.Authentication/MicrosoftAccountStore.cs) atomically binds an OeXYZ profile ID to exactly one protected Microsoft account, including concurrent first logins across multiple processes. |
| P1-6 | Concurrent profile saves caused failures and lost updates | [`ProfileRepository`](../src/OeXYZ.Core/ProfileRepository.cs) uses an interprocess lock, revisions, reload inside the lock, unique temporary files, three-way merge, and the transactional `Update` API. Both CLI and GUI use this boundary. Tests cover 20 concurrent repository instances and eight real worker processes. |
| P1-7 | Large status fields could trigger a stack overflow through `stackalloc` | [`MinecraftServerDiscovery`](../src/OeXYZ.Protocol/MinecraftServerDiscovery.cs) now uses heap-backed storage and limits version names to 256 characters and MOTDs to 4,096 characters. Fields as large as 128 KiB are truncated early and made terminal-safe. |
| P1-8 | A stale reconnect failure poisoned a later user disconnect | A successful reconnect clears the terminal failure state. CLI aggregation classifies `/disconnect` as a user stop and therefore excludes obsolete failures from the exit code. Session and CLI regressions cover both state transitions. |
| P1-9 | Release candidates could overwrite stable/`latest` | [`release.yml`](../.github/workflows/release.yml) validates SemVer tags, marks RCs as prereleases, and publishes `latest` only for stable versions. [`GitHubUpdateService`](../src/OeXYZ.Updater/GitHubUpdateService.cs) preserves the prerelease suffix and compares RC and stable versions correctly. |

## Fixed P2 Findings

| ID | Finding | Implementation and regression coverage |
|---|---|---|
| P2-1 | `doctor`, `healthcheck`, and key generation depended on valid profiles | Early command dispatch runs these commands before normal profile loading. `doctor` reports damaged configuration as a diagnostic with exit code 7 instead of crashing. |
| P2-2 | File-permission failures were classified as authentication failures because of `UnauthorizedAccessException` | CLI error mapping prioritizes `UnauthorizedAccessException` as an operational/internal failure (exit 70); a genuine authentication failure remains exit 3. |
| P2-3 | The wizard allowed 128 sessions while Compose allowed only 16 | [`SetupWizard`](../src/OeXYZ.Cli/SetupWizard.cs) and [`docker-compose.yml`](../docker-compose.yml) both use 16. A static regression test keeps the values synchronized. |
| P2-4 | Malformed profiles caused null-reference failures or accepted invalid values | [`ProfileDocument.Normalize`](../src/OeXYZ.Core/Profiles.cs) is the non-mutating Core boundary for null entries, IDs, enums, ports, names, settings, and session references. JSON and enum errors are classified as `InvalidDataException`. |
| P2-5 | CLI options consumed following switches as values | [`CliArguments`](../src/OeXYZ.Core/CliArguments.cs) rejects a missing value when the next token is another switch. `list --config --json` deterministically exits with code 64. |
| P2-6 | The dashboard validated the terminal only after session startup and wrote ANSI cleanup to redirected output | The terminal is validated before session startup; cleanup runs only if terminal mode was actually entered. Frames are also sanitized in full. |
| P2-7 | A custom installation path disagreed with the systemd unit | [`install.sh`](../install.sh) safely renders the actual literal path through `/usr/bin/env --`; spaces, `%`, `$`, backslashes, and quotes are covered. [`tests/install-systemd.sh`](../tests/install-systemd.sh) verifies the unit with `systemd-analyze --user verify`. |
| P2-8 | Explicit port `0` was treated as the default port | [`ServerAddress`](../src/OeXYZ.Protocol/ServerAddress.cs) rejects `:0`, `[::1]:0`, empty, negative, and oversized ports, including when an override is present. The CLI classifies this local input error as exit 64. |
| P2-9 | Multiple accounts on the same server were indistinguishable | Session titles, CLI prefixes, dashboard entries, and log names use `Account @ Server`. The multi-account test verifies both identities on the same server. |

## Additional Audit Fixes

- Account-store transactions now cover reload, authentication, profile binding,
  and save under a private, cancelable interprocess lock. Eight real child
  processes prove both lossless read-modify-write behavior and deduplication of
  concurrent first logins. Permanent I/O failures are no longer retried
  indefinitely.
- Windows DPAPI account data is limited to 8 MiB of plaintext, ciphertext is
  limited to 8 MiB + 16 KiB, and JSON depth is limited to 64. Unix key files
  are created with mode `0600` on the initial `CreateNew` open rather than
  through a later `chmod`.
- The NBT chat parser has global node, collection, and allocation budgets, a
  4,096-item list limit, and rejects non-empty `TAG_End` lists. Tiny
  allocation-bomb fixtures and legitimate nested components are tested.
- Session lines are limited to 4,096 characters and 256 formatting runs. Log
  and GUI buffers are fixed-size 1,024-entry drop-oldest queues. Diagnostics
  are limited to 200 entries and 131,072 characters. A real flood test verifies
  truncation, redaction, terminal safety, logs, and diagnostics.
- GUI profile mutations roll back after save or reload failures. Authentication
  identifier persistence failures do not escape into the session. During
  shutdown, persistence and cleanup failures are collected while every session
  cleanup is still awaited.
- Import names at the 64-character boundary are shortened without splitting
  UTF-16 surrogate pairs before the ` (imported N)` suffix instead of rejecting
  the entire import.
- Concurrent support-package exports use unique private temporary files and a
  serialized target replacement with bounded retries on Windows. Eight
  simultaneous exports were repeatedly verified without temporary-file
  residue.
- Installer temporary files for the binary and systemd unit are created with
  `mktemp` in the destination directory. Predictable `.$$` names and the
  associated symlink path have been removed.
- Pull-only Compose always refreshes the public GHCR `latest` image without a
  silent source fallback, while an explicit no-pull override retains direct
  repository builds. The Release workflow verifies the versioned manifest and
  pulls both AMD64 and ARM64 images through an empty credential store; after
  the GitHub release exists, fully queued and serialized promotion jobs allow
  only the newest stable version to promote `latest`.
- `.dockerignore` mirrors every local account, session, profile, key, runtime,
  and log exclusion relevant to `COPY . .`, so ignored credentials cannot enter
  a local or remote Docker build context. A static regression locks the list.
- CI and Release explicitly provision the commit-pinned Buildx action with the
  `docker-container` driver. A real builder exported an OCI index containing
  both AMD64 and ARM64 images, closing the default-driver release blocker.
- Previously duplicated atomic-write logic is consolidated in
  [`PrivateFileSystem.WriteAllBytesAtomically`](../src/OeXYZ.Core/PrivateFileSystem.cs).
  Profile rules are centralized in
  [`ProfileRules`](../src/OeXYZ.Core/ProfileRules.cs), and four real GUI
  behavior tests supplement the updater suite.
